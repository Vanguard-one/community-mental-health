# 2026-10-17

## 修：AI 问诊页点击后白屏（我上一轮改出来的）

**现象**：用户点「AI 问诊」加载不出界面。构建、类型检查全绿。

**根因**：`views/consult/AiChat.vue` 里我把等待态的初始化写在了 store 之前：

```ts
const SLOW_TIP_SECONDS = 4
watch(() => chat.sending, (sending) => { ... })   // ← 第 458 行
...
const chat = useChatStore()                        // ← 第 494 行
```

`watch()` **在定义时就会立刻调用一次 getter** 去取初始值，而 `const` 的暂时性死区
此刻还没结束 → `ReferenceError: Cannot access 'chat' before initialization` →
`setup()` 直接抛 → 整棵组件树不渲染 → 白屏。

**为什么构建没拦住**：`vue-tsc` 只做类型检查、`vite build` 只做打包，
**两者都不执行 `setup()`**。这类错误只能在运行时暴露。

**修复**：把「等待计时 + `thinkingText` + `showSlowTip`」整块移到
`const chat = useChatStore()` 之后，并在代码里留了注释说明为什么不许挪回去。

## 新增工具：`.workbuddy/scripts/setup_smoke.mjs`

**用途**：把 `.vue` 的 `<script setup>` 真的执行一遍，抓「setup 崩掉」这类
构建期查不出、运行时白屏的事故。

```bash
cd psycare-web
node ../.workbuddy/scripts/setup_smoke.mjs $(find src/views src/layouts src/components -name "*.vue")
```

**做法**：抽出 `<script setup>` → 用项目自带 `typescript` 擦类型 → 剥掉 import →
用 `new Function(...桩)` 顺序执行。桩尽可能贴近真实语义，**尤其是 `watch` 必须
立即求值 getter** —— 不这么做就复现不了这次的 bug。

**两处关键坑（都踩过）**：
1. **不能只注入「被 import 的名字」**：`defineProps` / `withDefaults` / `defineEmits`
   是**编译期宏**，源码里没有对应的 import；`window` / `document` / `getComputedStyle`
   是浏览器全局。它们的名字都不在 import 列表里 → 必须把全部桩常量都作为形参注入。
2. **`import.meta` 不能进 `Function`**（直接 SyntaxError），要先替换成字面量。

**边界（写在脚本头部，别当渲染测试用）**：
- 不求值 `computed`（惰性）→ 抓不到**渲染期**的错误。刻意不加，强求值会在
  `route.query.x.split()` 这类「要等真实数据」的闭包上误报一片。
- 不校验 props 语义（props 桩是宽容代理，取错属性不报错）。
- 不执行模板。

**灵敏度自证**（改动脚本后应重跑）：把 `watch(() => chat.sending, ...)` 挪回
`const chat = useChatStore()` 之前 → 工具报 `ReferenceError: Cannot access 'chat' before initialization`；
恢复后 → 通过。已实测两次。

**当前全站结果**：41 个 `.vue`（views / layouts / components）全部 `setup` 执行通过。

---

## 结论已沉淀

硬约定 **#129**：`watch` / `watchEffect` 这类「定义时即执行 getter」的 API，
必须写在其依赖的 `const` 之后；且**构建期检查不出这类错误**，需要
`setup_smoke.mjs` 兜底。

## 改：AI 问诊输入框改成拟物（soft UI）风格

**来源**：用户给的 Uiverse 样例（`box-shadow: 20px 20px 60px #c5c5c5, -20px -20px 60px #ffffff`，
focus 时同参数改 `inset`）。只改 UI，逻辑零改动。

### 关键判断：拟物必须与「所在面」同色，否则不成立

样例的控件底色 `#e8e8e8` 是**与它所在的面同色**的。本页原本输入区是 `--card-bg`（白），
消息区是 `--panel-bg`（#eef3fa）。直接套用会得到「白卡上贴一块蓝灰方块」——
两个阴影失去参照，看起来是平面色块而不是凸起。

→ 把 `.chat-input` 的底色改成 `--panel-bg`，与消息区统一成一个面。这也正对上了
`tokens.css` 里 `--panel-bg` 的既有注释（"只用于卡片内部的分区（表头、内嵌面板、**输入区**）"）。

### 新增 token（`tokens.css` 末段「拟物（soft UI）控件」）

| token | 值 | 说明 |
|---|---|---|
| `--neu-surface` | `var(--panel-bg)` | 必须与父容器背景同源；改父容器色要回来同步 |
| `--neu-shade` | `#c3d5ed` | = `--panel-bg` 在 HSL 上压暗 11 个亮度点（保留蓝色调），对面对比 **1.34** |
| `--neu-glow` | `#ffffff` | 对面对比 **1.11** |

**亮侧为什么比样例弱（1.11 vs 样例的 1.23）**：本项目的面（#eef3fa）比样例的 #e8e8e8
更接近白，「比它更亮」的空间更小。这是拟物在浅色系统里的先天上限 ——
唯一有效的旋钮是**把面压深**，给高光加不透明度没用（#ffffff 已经最亮了）。

### 与样例的三处刻意差异

1. **尺寸收敛**：`padding 1rem / 偏移 20px / 模糊 60px` → `8px 15px / 5px / 14px`。
   照搬会让阴影外扩 80px 铺到消息区，且一行输入被撑到 60px 高、与 32px 发送按钮错位。
2. **焦点不吞 outline**：样例 `outline-color:#e8e8e8` 等于把键盘焦点圈涂成背景色，
   按 Tab 完全看不出焦点。改成「内凹 + `inset 0 0 0 1.5px var(--primary)` 内圈」。
3. **圆角 16px**（对齐 `--radius-sm`），并把占位符从 `--text-3` 提到 `--text-2`。

### 连带修掉的一处对比度

`.closed-text`（"该会话已结束"）原是 `--text-3`，在白底 4.8 达标；输入区底色换成
`--panel-bg` 后掉到 **4.27**（不达 AA）→ 改 `--text-2`（6.94）。
**这就是「换底色」最容易漏的连坐**：同一文件里凡是落在该区域上的 `--text-3` 都要重算。

### 自检

`setup_smoke.mjs` ✓；CSS 花括号 180:180 平衡；`vue-tsc -b` 0 error；
`vite build` ✓ 1.92s；`vendor-antd` **714.54 kB**（零膨胀）。
`#e8e8e8` 仅剩注释里一处引用（非声明，合规）。

## 改（第二版）：拟物被否，换成「下划线 + 聚焦渐变线」

**用户反馈**：拟物那版「感觉不好看」，给了新样例（Uiverse / adamgiebl）：
静止一条 `border-bottom`，聚焦时一条 `linear-gradient(90deg, #FF6464, #FFBF59, #47C9FF)`
的 3px 线在 `width: 0% → 100%` 之间铺开。

### 上一版整套撤回（不留死代码）

- 删 `tokens.css` 的 `--neu-surface/shade/glow` 及整段注释
- `.chat-input` 底色 `--panel-bg` → 回 `--card-bg`
- `.closed-text` `--text-2` → 回 `--text-3`（白底 4.8 达标）

> ⚠️ **拟物与下划线是两种「成立条件相反」的风格**：
> 拟物要求「控件底色 == 所在面」，下划线要求「控件透明、只留一条底线」。
> 换风格时必须把上一版的前置条件一起撤掉，否则 `--panel-bg` 这种为拟物改的底色
> 会残留下来，把下划线输入框衬得像「白卡里挖了一块蓝灰」。

### 落地

| 位置 | 改动 |
|---|---|
| `tokens.css` | 新增 `--grad-underline`（红→琥珀→蓝）。**注释写明这是全站唯一一处纯装饰性彩色**，与「彩色只承载风险语义」的体系冲突，换 `--grad-primary` 即可改回协调版 |
| `AiChat.vue` 模板 | 给 `a-textarea` 套 `.composer` 壳 + 兄弟节点 `.composer-line`（绝对定位的动画线） |
| `AiChat.vue` 样式 | 输入框改透明底 + `border-bottom: 2px`；聚焦时底线转 `transparent` 让位给 3px 渐变线 |

### 三处关键判断

1. **不用样例的 `.input:focus + .input-border` 相邻兄弟选择器**，改用 `.composer:focus-within`。
   相邻兄弟要求「span 紧挨在 input 后」，而 antd 的 textarea 在不同属性下可能被包一层，
   那时 `+` 会**静默失效**（线永远不出现、无任何报错）。`:focus-within` 只看焦点在不在壳里。
2. **聚焦时必须把 `border-bottom-color` 设成 transparent**。渐变线 3px + 底线 2px 同时可见
   会叠成 5px 的双色边（下半灰、上半渐变），看起来像描边错位。
3. **`.composer-line` 必须 `pointer-events: none`**。它压在下沿 3px 上，不关命中测试的话
   点输入框最下面 3px 会点到 span 而不是 textarea。

### 另外两处刻意偏离样例

- **删掉 `box-shadow: 0 4px 8px rgba(0,0,0,.1)`**。样例是深色背景，投影负责让透明框「浮」起来；
  本项目输入区是白卡，无填充矩形投出的影子在浅底上只会像污渍。
- **字号 `1.2rem` → 15px**。19px 是给独立表单大输入框的，塞进一行高的对话输入条会与 32px
  发送按钮不成比例。

`setup_smoke.mjs` ✓；CSS 花括号 185:185；`--neu-` 残留 0；`vue-tsc -b` 0 error；
`vite build` ✓ 8.70s；`vendor-antd` **714.54 kB**（零膨胀）。**待用户刷新验收**。

## 改（第三版）：发送按钮换成「圆环 + 箭头」样例

**来源**：Uiverse / xopc333。`a-button` 整体替换为原生 `<button>`。样式全放在本文件（无新 token，
复用 `--primary` / `--primary-dark`）。

### 与样例的五处差异

| # | 样例 | 这里 | 原因 |
|---|---|---|---|
| ① | `rotate(180deg)`（箭头朝左） | **`rotate(-90deg)`**（朝上） | ⚠️ CSS `rotate()` **正角是顺时针**（y 轴朝下）；写成 `90deg` 箭头会朝下 |
| ② | `.button-box` 横向 `translateX(-56px)` | **`flex-direction: column` + `translateY(-40px)`** | 箭头朝上后还横向滑，读起来是「横向平移」而不是「往上送出」 |
| ③ | 56×56 | **40×40** | 输入框仅约 38px 高，56 会把输入区顶高一大截且与底线不在同一基线 |
| ④ | `#f0eeef` 浅灰（给深色背景） | **`--primary` / 悬停 `--primary-dark`** | #f0eeef 对白只有约 1.1:1，在白卡上等于看不见 |
| ⑤ | 无 loading / disabled | **自绘 `.send-spin` + `:disabled`** | 原来是 `a-button`，这两个状态由 antd 提供；换原生 button 必须自己补，否则发送期间看不出在工作、还能重复点 |

### 尺寸算术（不是估的，是推出来的）

```
按钮 40×40
  圆环 inset 5px → 环外框 30×30，border 3px → 内孔 24×24
  箭头 16×16 居内孔
  每个 .send-elem 占位 = 16 + 12×2 = 40 = 按钮高度
  → translateY(-40px) 刚好吃掉一格，不会半格错位
```

### 三处容易踩的实现细节

1. **`:not(:disabled):hover`**。原生 button 在 disabled 时**仍会匹配 `:hover`**，
   靠「把 disabled 规则写在后面」很脆，以后中间插一段样式就复现。
2. **`:focus-visible` 额外补实心 outline**。样例把 `:focus` 和 `:hover` 写在同一组选择器里，
   导致键盘焦点与鼠标悬停长得一模一样 —— 而悬停是**瞬时**的、焦点是**持续**的，
   Tab 过来的用户无法分辨「我现在停在这个按钮上」。`overflow: hidden` 不会裁掉自身 outline。
3. **`prefers-reduced-motion` 下转圈不关**。它是「正在发送」唯一的反馈，停掉之后用户
   只能反复点击。去掉滑移/缩放即可，转圈属于「表达状态所必需」。

### 顺带修掉

`.as-item.is-done .as-mark` 的 `color: #fff` → `var(--on-primary)`（同文件既有的硬编码，主色底上的白字）。

### 自检

`setup_smoke.mjs` ✓；CSS 花括号 205:205；本文件 `a-button` 仅剩侧栏两个 `side-link`（未动）；
样式内硬编码色值 0（`#ff4d4f` 仅注释）；`vue-tsc -b` 0 error；`vite build` ✓ 8.43s；
`vendor-antd` **714.54 kB**（换掉一个 a-button 不影响，别处仍在用）。

## 改（第四版）：「AI 推荐」等待动画换成方块翻滚

**来源**：Uiverse / alexruix。替换 `.analyze-orbit`（两条同心圆 + 旋转高亮弧 + 「AI」实心核）。

### 刻意保留的东西

**标题「正在为你匹配医生」与三步文案（读取测评 → 梳理对话 → 匹配医生）全部保留**。
原代码注释里已写明这个取舍：「推荐本身是后端毫秒级算完的，直接跳转会让用户什么也没看见
就换了一页」，三步文案是这段等待里**唯一的信息量**。换成纯 loader 会让整段等待退化成
「卡了一下」，反而削弱推荐的公信力。→ 只换视觉，不动文案。

### 颜色（浅蓝色系）

| 部位 | 取值 | 结果 |
|---|---|---|
| 方块 | `color-mix(in srgb, var(--primary) 45%, var(--card-bg))` | ≈ `#9db9f6` |
| 地面影子 | `color-mix(in srgb, var(--primary) 22%, transparent)` | ≈ `rgba(37,99,235,.22)` |

**为什么用 color-mix 而不是直接写浅蓝**：直接换一个浅蓝色号就是一个固定值，
而混 `--card-bg` 有两点好处 —— ① 底色跟着卡片走，将来改白卡色自动协调；
② 不需要新增 token，也不是硬编码（全站已有 `color-mix(... var(--primary) ...)` 的先例）。

### 两个容易写错的地方

1. **100% 必须停在 `rotate(90deg)`，不能写 `rotate(0)`**。正方形转 90° 与不转看起来完全一样，
   所以循环回到 0% 无跳帧；而圆角在中途被改过（3px / 40px），若把终点写成 0° 会硬切回去，
   每轮都能看到「抖一下」。
2. **影子 `top: 60px` 是故意溢出 48px 容器的**（60+5=65）。影子本来就该落在方块起跳的
   那块空地上，所以下面给了 `margin-bottom: 24px` 让位。改成 `top: 48px` 会让影子贴着方块底部，
   「跳起来」的空间感就没了。

### 减动效

`prefers-reduced-motion` 下把「翻滚」换成 1.6s 的**缓慢呼吸**，而不是停掉 ——
停掉的方块和一张静态图没有区别，用户会以为界面卡住。影子同时停止缩放（独自缩放更奇怪）。

### ⚠️ 已知的对比度缺口

`#9db9f6` 在白卡上只有约 **1.96:1**，低于 WCAG 1.4.11 对「有意义的图形」要求的 3:1。
这是「浅蓝色系」这个要求本身的代价（浅色压白底必然低对比）。它靠**运动**被看见而不是靠对比度，
在 48px 尺度上可接受；若觉得太淡，把混色比例从 45% 提到 60%（≈ `#7ca1f3`，2.5:1）或 70%。

### 自检

`setup_smoke.mjs` ✓；CSS 花括号 215:215；旧轨道样式（`analyze-orbit` / `orbit-ring` / `orbit-core` /
`@keyframes orbit`）残留 0；`@keyframes` 13 个无重名；样式内硬编码色值 0（`#9db9f6` / `#f08080`
仅出现在注释里说明色值）；`vue-tsc -b` 0 error；`vite build` ✓ 7.75s；`vendor-antd` 714.54 kB。

## 改（第五版）：左侧栏悬停交互（Tailwind → 原生 CSS）

**来源**：Uiverse / Mayurwaghgpr 的横向表情条（全 Tailwind 类名）。项目没装 Tailwind，
用户要求**只改交互动画、保留既有图标样式**，应用到 `SideRail.vue`。

### 不逐条翻译工具类，只提取「它实际在做什么」

Tailwind 那串类名拆开只有四件事：`hover:-translate-y-5`（弹起）、`hover:scale-125`（放大）、
`::before` 画出文字标签、容器 `hover:scale-x-105`。按本项目的写法重做这四件事即可，
**一行 Tailwind 语义都不用搬**。

### 落地时的四个判断（都不是照抄）

1. **方向必须从「向上」改「向右」**。样例是横向条，`-translate-y` 等于「离开条、靠近你」；
   本项目是 64px **纵向栏**，上下平移会被读成「图标在栏里往上滑」，语义完全不同。
   纵向栏里同义的「弹出」方向只有朝内容区（+X）。位移取 **5px** 而非 10px：
   栏宽 64、块宽 44，左右各剩 10px，给满就会顶到栏的描边上。
2. **放大图标，不放大 44px 的块**。块一旦 `scale`，里面的提示气泡（`::after` 是块的子元素）
   会跟着放大 —— 12.5px 文字被拉到 14px 以上会发虚；且块放大到 1.25 会与上下相邻项
   **仅 6px 的间距**挤在一起。只放大图标（`:deep(svg)` 1.18）就能保留「弹一下」的手感且不动布局。
3. **`transform` 必须写进 `transition` 列表**。只在 `:hover` 里加 transform、忘了加进过渡，
   表现是「瞬间跳过去」而不是「弹出去」，看起来像卡了一下。
4. **`transform` 会创建层叠上下文 → 提示气泡的 `z-index: 60` 从此失效**（只能在元素内部比较）。
   必须给悬停项本身抬 `z-index: 3`。不做这一步，气泡会被**后面的菜单项盖住**，
   表现为「提示只露一半」—— 这是本轮最隐蔽的一处。

### 刻意没做

容器的 `hover:scale-x-105`：整栏横向拉伸会让 `position: fixed` 的侧栏与内容区错位，
且 64px 的栏横拉 5% 只有 3px，收益为零、代价是布局抖动。

### 提示气泡

与主色块**同向弹出**：`translate(-6px,-50%) scale(.9)` → `translate(0,-50%) scale(1)`，
`transform-origin: left center`（锚在左边才像「从图标旁边冒出来」；默认中心缩放会往两边长）。
起点用 `scale(.9)` 而不是 0 —— 从 0 放大在 12.5px 小字上会有一帧发虚。

### 减动效

去掉位移与缩放，**保留颜色变化与气泡淡入** —— 颜色承担「你正指着哪一项」这个信息，
不是动效；要砍的只是会引起前庭不适的位移/放大。

### 自检

`setup_smoke.mjs` ✓（SideRail / DefaultLayout / AdminLayout）；CSS 花括号 17:17；
`transform` 已进 transition、`z-index: 3` 已加、`prefers-reduced-motion` 已写；
`vue-tsc -b` 0 error；`vite build` ✓ 1.88s；`vendor-antd` 714.54 kB。

## 改（第六版）：AI 回复前的等待动画换成八点旋转脉冲

**来源**：Uiverse / abrahamcalsin。替换 `.tw-dots`（三点跳动）。**保留**阶段文案与「超过 4s」的补充说明。

### 原理（不是「旋转」）

8 个 `<i>` 各转 45° 均匀铺在圆周上，每个里的圆点共用同一条 keyframes，
只把 `animation-delay` 依次错开 `-0.125` 个周期 → 「正在放大的那个点」看起来在沿圆周跑。
**没有任何元素真的在转**，整段动画只有 `scale` + `opacity`，直接走合成层。

> ⚠️ 步长必须是 1/8 的倍数，否则接缝处会顿一下。

### 与样例的三处差异

| # | 样例 | 这里 | 原因 |
|---|---|---|---|
| ① | `--uib-size: 2.8rem`（44.8px） | **28px** | 塞进 13px 文字的对话气泡会把行高顶到 45px，一行等待文案被撑成一大块 |
| ② | `box-shadow: 0 0 20px rgba(18,31,53,.3)` | **去掉** | 样例是深色背景，光晕负责把点托起来；本气泡是白卡，深色光晕在浅底上只会晕成灰雾，且缩小后模糊半径等比跟着缩，会盖住一半的点 |
| ③ | `#183153` | **`var(--primary)`** | 色值只走 token |

### ⚠️ 减动效里的一个特异性坑（本轮新增教训）

第一版写成 `.think-spin > i::before { animation: think-breathe ... }`，**无效**。
因为上面 8 条 `.think-spin > i:nth-child(2..8)::before { animation-delay: ... }`
特异性更高（多一个伪类），而 `animation` **简写会把 delay 一起重置**，但输给了那些
更高特异性的 `animation-delay` 声明 → 结果「换了 keyframes，错开的延迟还在」，
点与点之间仍在绕着跑，等于没减动效。

**正解**：选择器写成 `:nth-child(n)`（与 `:nth-child(2)` 同特异性），且**位置写在它们之后**，
显式 `animation-delay: 0s`。→ 8 个点同时呼吸。

> 通用判据：用 `animation` 简写去覆盖某组 `animation-delay` 时，**先看特异性**；
> 简写不是「万能重置」，它只是又一条声明。

### 顺带移除

`.tw-bar`（不确定流动进度条）同时下线 —— 8 点脉冲已经足够表达「在进行」，
再叠一条扫光条是两套重复的活动指示，反而显噪。**文字文案与 slow tip 保留**。
若要恢复进度条，样式与 `@keyframes tw-sweep` 在 git 历史里。

## 改（第七版）：首页「最近记录」改成分级提示条

**来源**：Uiverse / Cybercom682 的四色 alert（Tailwind）。落到 `views/home/Home.vue`，
四色映射到风险等级 **A/B/C/D**（低/中/高/危机）。

### 版式

`[左缘 4px 实色条][16px 同色图标][量表名 + 时间][RiskLevelTag(plain)]`

行底色 = `--risk-*-soft`，左缘条 = `--risk-*` 实色，图标 = `--risk-*-ink`。
三者由 `.lv-a/b/c/d` 注入的三个自定义属性（`--rec-accent` / `--rec-bg` / `--rec-fg`）统一驱动，
组件内不出现任何色值。原 `.rec-dot` + `.dot-a..d` 已删除（图标取代了它）。

### ⚠️ 三处必须改的地方（都是实测出来的，不是审美）

1. **时间那一行必须从 `--text-3` 提到 `--text-2`**。行底色一换成 `--risk-*-soft`，
   `--text-3` 在四档上分别只有 **4.31 / 4.42 / 4.27 / 4.40 —— 全部不达 AA 4.5**。
   `--text-2` 是 6.94~7.19。**这是「改行底色」必查的连坐项**（同 #130 ④）。

2. **`RiskLevelTag` 必须传 `plain`**。默认模式的 `--tag-bg` 就是同族 `--risk-*-soft`，
   与本行底色**完全一样** → pill 隐形，只剩一行彩色文字浮在行里。
   `plain`（透明底 + ink 描边 + ink 文字，4.69~5.77）在浅底上才立得住。

3. **悬停只放大，不改底色**。样例是「底色加深一档 + `scale-105`」，但底色一加深，
   压在行上的 `--risk-*-ink` 就掉到 4.5 以下（实测混 8% 即 4.37~4.48，混 14% 掉到 4.12~4.27），
   而右侧标签用的正是 ink 色 —— **鼠标一悬停文字就不达标**。所以砍掉「加深底色」，
   只留最有辨识度的「放大」。
   `scale` 也从 1.05 收到 **1.02**：行接近全宽，1.05 右端会多出十几像素顶到卡片内边距；
   1.02 约 7px，是「确实动了」但不越界的量。

### 其他

- 行间距 `gap: 6px`（样例是 `space-y-2` 即 8px）。**不能是 0** —— 否则 `scale` 会与上下行直接贴住。
- 图标 20px → 16px：行高约 44px，20px 的图标会把两行文字挤扁。
- 没加投影：卡内分区叠阴影会发脏（面分级规则 ②）。
- `transform` 已写进 `transition`，`transform-origin: left center`（向右顶出，不往卡片左内边距里挤）。

`setup_smoke.mjs` ✓；CSS 花括号 51:51；`rec-dot` / `dot-a..d` 残留 0；`.lv-a/b/c/d` 四档齐；
新增样式内硬编码色值 0（405–413 行的 8 个 hex 是既有的快捷入口图标砖，未动）；
`vue-tsc -b` 0 error；`vite build` ✓ 1.97s；`vendor-antd` 714.54 kB。

## 改（第九版）：评测中心量表卡片换成新卡片格式（浅蓝）

`components/ScaleCard.vue` 重写 + `assessment/ScaleList.vue` 同步骨架屏。
来源：Uiverse / Javierrocadev 的卡片（深色系 + 三个图标按钮）。

### 内容裁到四样

表名 / 维度标签（如「抑郁」）/ 简要描述 / 底部「开始测评」条。
去掉：量表编码（PHQ9）、题数、满分。

⚠️ **`code` / `itemCount` / `maxScore` 三个 prop 必须一并从组件删除**，不能只从模板删。
Vue 会把未声明的 attr 作 fallthrough 落到根元素上，DOM 里会出现 `itemcount="9"`、
`maxscore="27"` 这类无意义属性。`ScaleList` 那边的绑定也同步删了。

### 配色：不能照抄样例的半透明底

样例 `background: rgba(105,13,197,0.103)` 是压在**深色页面**上的 —— 透出来仍是暗底，
所以近白文字（aliceblue）能读。本项目页面底是浅蓝渐变 `#c6d9f5 → #d3e1f8`，
同样半透明透出来还是浅色，卡片整块糊进背景（也会撞上「贴页面底的面只能是白卡或主色」那条规则）。

改成 **`color-mix(in srgb, var(--primary) 8%, var(--card-bg))`**：

| 指标 | 实测 |
|---|---|
| 卡对页面两端 | **1.30 / 1.20**（白卡基准 1.32） |
| `--text-1` | 16.5 ✓ |
| `--text-2` | 6.8 ✓ |
| `--primary-dark` | 5.9 ✓ |

同理两处**样例色必须自己给**：
- 装饰圆环：样例是 `rgba(255,255,255,.102)` 的白环，在白/浅蓝底上等于不存在 → `--primary` 18%
- 底部按钮条：样例 `rgba(247,234,234,.589)` → `--card-bg 72%` 半透明白

### 三处实现要点

1. **装饰圆环是定位元素，会盖住文字**。`::before` 是 `position: absolute`，
   按绘制顺序会压在被它遮住的**静态流内容**上面 → 那圈模糊光会糊在表名上。
   `.body` 与 `.foot` 必须显式 `position: relative; z-index: 1`。
2. **标签改描边式**。原实底 `--primary-soft` 落在已带蓝调的卡片底上边界几乎看不出；
   且 `--primary-soft` 底 + `--primary` 字只有 **4.44**（不达 AA）。
   描边式两头都解决：描边 4.7、文字 `--primary-dark` 5.9。
3. **骨架屏必须同步**。`.sk-card` 的 `min-height 172 → 200`、`padding 22/24 → 16/18`、
   底色改浅蓝、去掉 1px 描边。只改真实卡片不改占位块，加载完成那一下会有
   **高度突增 + 底色突变**两道闪。

### 没做的

样例底部那排三个图标按钮没有搬 —— 这里只有一个「开始测评」入口。
按钮条是**整条可点**（卡片本身就是入口），没再套一层 `<button>`，
否则会出现「点外圈能进、点按钮也能进」两套语义。

`setup_smoke.mjs` ✓（ScaleCard / ScaleList）；两份样式花括号 11:11 / 15:15；
`defineProps` 各 1 次（第一版误写了两处，已修）；新增样式内硬编码色值 0
（`#c6d9f5` / `#d3e1f8` 仅出现在说明页面底的注释里）；
`vue-tsc -b` 0 error；`vite build` ✓ 6.01s；`vendor-antd` 714.54 kB。

**后续微调（同日）**：装饰环按用户反馈「往下移一点、蓝光稍微大一点」调整 ——
静止 `100→116px`、`top -40%→-34%`；悬停 `140→152px`、`top -30%→-26%`。
判据是「露在卡片内的弧长」而不是尺寸本身：静止 20px → **48px**、悬停 80px → **100px**

## 改（第十版）：登录页最外层背景换成 WebGL「马赛克透镜」

**来源**：Originkit 的 `MosaicLens`（React + 双通道 WebGL2）。新建
`components/MosaicLens.vue`（Vue 移植），挂在 `views/auth/Login.vue` 的 `.auth-lens`（fixed 层）。

### 它算什么

```
pass 1  field  → 离屏 FBO（优先 RGBA16F）
         每像素 74 次「折叠 + 扭曲」迭代，累加成光丝场。唯一贵的部分。
pass 2  finish → 屏幕
         把 field 按马赛克格子取样；格子大小按「离指针距离」分 4 档，
         指针附近最细（base/2^3）、越远越碎。
```

### 移植时四处必要改动（**不是偷懒**）

| # | 原实现 | 改成 | 原因 |
|---|---|---|---|
| ① | `minWidth: 1200, minHeight: 800` | **删掉** | 那是给「独立演示块」的；当全页背景会在窄屏撑出横向滚动条，并把页面顶成 800px 死区 |
| ② | field 固定 `bw/2`，无上限 | **宽度封顶 896** | DPR2 的 1440 宽屏幕上 `bw/2` = 1440 宽 ≈ 130 万像素 × 74 层 ≈ 一帧近 1 亿次迭代（每层含 3 个 sin + 1 个 exp2，高开销指令），集显直接掉帧。896 ≈ 45 万像素，成本回到原演示量级；pass 2 反正要马赛克化，肉眼看不出来 |
| ③ | 色值写在 props 默认值 | **读 CSS 变量** `--lens-bg / --lens-c1 / --lens-c2` | 本项目色值只放 tokens.css。props 仍可覆盖。色值解析失败返回 `null` 走兜底，**不抛异常**（一个拼错的色值不该让整个背景消失） |
| ④ | 只有 RAF 循环 | **补减动效 + 页面隐藏暂停** | 全屏 60fps 流动纹理正是 reduced-motion 要避开的；取「冻结的第一帧」（不能不出图，否则是一块纯色）。`document.hidden` 时停 RAF |

### Login.vue 的一处连带删除

**删掉了 `.auth-wrap::before`**（两团 `rgba(255,255,255,.55/.4)` 的径向光晕）。
它的作用是给「平面渐变底」提亮；换成马赛克后，那两团白雾会盖在左上/右上，
把最精细的纹理糊掉。

层级：`.auth-lens { position: fixed; inset: 0; z-index: 0; pointer-events: none }`，
`.auth-frame { z-index: 1 }`。`pointer-events: none` 不影响透镜 ——
组件内部监听的是 **window** 的 pointermove，不依赖 canvas 命中。

### 降级链

WebGL2 不可用 → 纯色底（`.lens` 的 `background-color: var(--lens-bg)`）；
着色器编译/链接失败 → 同上并打 `console.error`（把 infoLog 一起打出来，
否则「背景没出来」只能猜是哪段 GLSL 错）；
`EXT_color_buffer_float` 缺失 → RGBA16F 自动退 RGBA8（亮部会被裁，偏硬但不黑屏）。
