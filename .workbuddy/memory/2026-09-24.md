### 遇到的坑（重要，可复用）

1. **`batch_edit` 的 `I(parent, ...)` 父级 ID 写错**：医生端工单列表误挂在「主区域」而非「工作区」，导致左右分栏塌成上下堆叠，渲染错乱。批量写 ops 时父级 ID 必须逐个核对。
2. **`U(node, {svg: ...})` 无法替换已有 SVG**：返回 `updated:{}`，静默失效。要换图标/图形必须 `D()` 删除后 `I()` 重建，再用 `M(newNode, parent, index)` 调回正确位置。
3. **`stroke-dasharray` + `stroke-dashoffset` 画环形图渲染异常**（弧段长度与位置全错，且底色圆环不显示）。**可靠做法：用显式 `A` 圆弧 `path` 命令**（先算好起止点坐标与 large-arc / sweep 标志）。同文件里的折线图（M/L + circle）与矩形/文字 SVG 渲染均正常。
4. **`fill_container` 高度的嵌套链会失效**：`fixed 高度 → fill → fill → fill 子节点` 多层传递时，最内层 `fill_container` 孩子被压成 1px。诊断靠 `capture_layout`，修法是给最内层一个固定高度。
5. `capture_layout` 的 `LARGE_EMPTY_AREA` 多为设计意图（侧栏 SPACE_BETWEEN 分布、卡片等高拉伸），不必然是缺陷，需结合截图判断。

### 关键方法论（可复用）

1. **SVG 在画布中是普通子节点，可独立改色**：图标里的 `VECTOR`/`ELLIPSE`/`RECTANGLE` 可以直接 `U()` 改 `fills`/`strokes`。**全局换肤只需改属性，不要重画图标**——这是把 10 屏换肤从"几小时"压到"十几分钟"的关键。
2. **批量换肤的正确工作流**：`batch_read` 按页拿全量 `fills/strokes` → 在脑内建"旧值 → 新值"映射表 → 按页 `batch_edit`（每批 ≤25 ops）→ `capture_layout(problemsOnly)` 扫布局 → 最后一批 `capture_screenshot` 复核。
3. **前 4 屏内部就有色值不一致**：换肤时不要假设"同一语义 = 同一色值"，必须逐节点读出来看，否则改一半漏一半。
4. ✅ **本模型可以读图**（上一轮会话"不支持读图、Read 返回 Content filtered"的结论是错的）。下载截图后用 Read 工具即可正常看到画面。截图存到项目内的临时目录后要记得删除（`rm -rf .workbuddy/_verify`）。

### 本轮踩坑（全部通过截图才发现，构建与类型检查完全测不出）

1. **`a-layout` 用原生 `<aside>` 侧栏会塌**。antd 只在子节点是 `a-layout-sider` 时才加 `ant-layout-has-sider`（切 `flex-direction: row`），否则退回默认 `column`，侧栏变成顶部一条 232px 宽的横条。
   修法：给外层显式 `flex-direction: row`。
2. **CSS 自定义属性不能向父级冒泡**。`:style="{'--icon-color': ...}"` 原写在图标 `<span>` 上，但 hover 时父级 `.entry-card` 取不到 → 必须挂在最外层元素。
3. **高 DPI Windows 上 Chrome headless 会缩放约 1/3**，第一张截图内容只占左侧 480px、字体极小，一度误判为布局 bug。加 `--force-device-scale-factor=1` 后正常。
4. **Read 工具展示图片时会缩放**，按屏幕像素判断"内容没占满宽度"是错的——真实内容区 1296px（1344 − 2×24 内边距）完全正确。
5. **JetBrains Mono 的 `0` 在 ≤11px 下与 `8` 混淆**（`0–7` 读成 `8–7`）。用 `--dump-dom` 拉真实文本才排除。已把标尺刻度提到 12px + `--text-2` 加深。
6. **`RiskScale` 的等分回退分界在切点处重叠**（`0–7` 与 `7–14` 都以 7 结尾），本身不严谨。已改为**仅在调用方传入真实 `bands` 时才显示区间数字**。

### 后端机制澄清（一度误判为 bug）

提交 PHQ-9 得 9 分（每题为 1 分）时返回 `rawLevel: "轻度"` 但 `riskLevel: "D"` + `crisis: true`，初看像分级错误。
实际是 `ScoringEngine` 的**有意设计**：`crisisFlag=1` 的题（PHQ-9 第 9 题=自杀意念）只要得分 > 0 就强制 D 级、绕开普通分级。我的测试答案恰好给第 9 题也打了 1 分。
→ 衍生注意点：`rawLevel`（临床五级：无/轻度/中度/中重度/重度）与 `riskLevel`（系统四档 A/B/C/D）是两套体系，前端不要混用。`Result.vue` 同时展示二者，是既有设计。

**本轮踩到的真坑（都是构建测不出的）**

- **`a-spin` 会插入两层包裹 div，打断 flex 链**：`.stage` 的 `flex:1` 与外层 `min-height` 失去联系，
  整页撑不满。解法是 `:deep(.ant-spin-nested-loading/.ant-spin-container)` 透传 flex。
- **`box-sizing: border-box` 下 `min-height: calc(100vh - header - 2*padding)` 重复扣减 padding**，
  底部矮掉一整块。正确写法只减 header。
- **SSE 一个事件内可能有多行 `data:`**（LLM token 自带换行时 Spring 会拆行），
  必须按规范 `join('\n')` 还原，否则回复段落全连成一行。实测后端返回正是 4 行 `data:`。
- **`rawLevel`（临床五级）与 `riskLevel`（系统四档）会矛盾**：危机项阳性时 rawLevel 仍是「轻度」。
  两者并列展示会让人误读，前端必须改写文案。
- 排查标尺配色时被**截图缩放**误导，以为 B 段变蓝；用 1:1 小视口重截才确认正常。
