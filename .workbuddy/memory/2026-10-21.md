## 管理端「评测筛查表管理」：启用 / 禁用 / 删除（新增功能）

**范围**：`/admin/scales` 新页面，治理四张筛查表（PHQ9 抑郁 / GAD7 焦虑 / PHQ15 躯体化 / PSQI 睡眠）。
**新增筛查表按需求暂缓**：按钮保留为 disabled 态 + 原生 title 说明，不做弹窗、不留半成品接口。

### 核心决策：删除 = 逻辑删除，不是 DELETE

引用链：`assessment.scale_id`、`assessment_answer.item_id / option_id`。
物理删除会让 `AssessmentRecordMapper.xml` 那两条 `JOIN scale` 的查询**直接查不出数据** ——
居民测评历史列表会空、工单右栏纵向对比会断、逐题明细丢卷名。

所以：
- 走 `scale.is_deleted`（对齐全局 `logic-delete-field: isDeleted`，与 `sys_user`/`banner` 同一套约定）
- 删除时**额外把 status 置 0**：逻辑删除只作用于 BaseMapper 方法，报表/原生 SQL 仍可能扫到该行，顺手上一把锁
- `scale_item / scale_option` **不删**：`assessment_answer` 引用它们，`selectAnswerRows` 还要 JOIN 出题干与作答文案
- 历史记录仍可看：MP 的逻辑删除只注入 BaseMapper 生成的方法，**XML 手写 SQL 原样执行**，`JOIN` 仍能取到软删行的 name/code（`AssessmentService.getRecord` 的 `scale != null : "未知量表"` 就是为这个场景写的）

**已验证的 null 安全点**（删表后不会 500）：
`AiConsultService.scaleNameOf`（`scale == null → null`）、`RecommendService`（`if (scale != null) dimension=...`，退化为无维度匹配，引擎本身有冷启动兜底）。

### 启停传目标值，不做 toggle

`PUT /scale/{id}/status?status=0|1`。toggle 在两种真实场景会翻回去：
① 双击（两次都取反当前值）；② 两管理员并发。目标值天然幂等。

### DDL 风险与自动补列

`Scale` 实体加 `isDeleted` 后，全局配置会**给所有** BaseMapper 查询追加 `is_deleted = 0`。
库缺这列时不是"删除不可用"这么局部，而是**量表列表 / 问卷详情 / 提交测评全线报 Unknown column** —— 本地极难归因。

因此新增 `config/ScaleSchemaInitializer`（`ApplicationRunner`，`@Order(-100)`）：
启动时查 `information_schema`，缺列则 `ALTER TABLE scale ADD COLUMN is_deleted`。
用 `DataSource` + 原生 JDBC（**不用 JdbcTemplate**：项目没显式引 `spring-boot-starter-jdbc`，装配不可靠）。
失败只 `log.error` 不阻断启动，日志直接指路 `sql/v12_scale_manage_ddl.sql`。
⚠️ 正式环境应由迁移工具执行 DDL，自动补列是本地/演示环境的取舍，注释里已写明。

## 首页 banner 去白框：真正的白边一直在 CSS 容器上

**用户诉求**：banner 图上的白色边框全部去掉，只留图；不残留边框 / 留白 / 外边距；各屏幕尺寸观感一致。

### 归因（先分清「CSS 容器」还是「图片文件自带白边」）

`.banner-carousel` 当时同时挂着四样东西，每一样都单独构成视觉边框：

| 属性 | 造成的效果 |
|---|---|
| `background: var(--card-bg)` | 白卡底 —— 图片没盖满的地方就是白的 |
| `padding: 12px 14px 14px` | 图四周一圈实打实的白边 |
| `box-shadow: var(--shadow-card)` | 图外再圈一层柔和边界，看起来仍"嵌在一张卡里" |
| `border-radius` | 容器不可见后只剩「给透明盒子倒角」 |

**图片侧也查了**（这条不能省：用户说白边时，可能是素材本身带的，改 CSS 永远改不掉）：
用 PIL 逐行/逐列扫「是否整行整列 ≥245」，实测库里 3 张上传图——

| 文件 | 尺寸 / 比例 | 四边白像素 | 结论 |
|---|---|---|---|
| `c59a764d….png`（banner id=1） | 1920×1072 / 1.79 | 0% | 干净 |
| `5facdcde….jpg`（banner id=2） | 1200×480 / **2.50** | 0% | 干净，与容器比例完全吻合 |
| `5627a3fc….png`（**无记录引用**） | 1044×1053 / 0.99 | **100%** | 白边 上47/下60/左126/右148px，占面积 33.7%，孤儿文件 |

结论：**在用的两张图都是 0% 白边，用户看到的框 100% 来自 CSS 容器**。那张带白边的图是上传后没被启用的残留文件，不影响首页。

### 改动

`components/BannerCarousel.vue` 的 `.banner-carousel` 只保留布局职责，删掉 `background` / `padding` / `box-shadow` / `border-radius`。

**保留的三样，都是「图片本身的形态」而非边框**：
- `.slide` 的 `border-radius: var(--radius-sm)` + `overflow: hidden`（图四角圆角）
- `.slide` 的 `background: var(--primary-soft)`（图未加载时的占位，不是白）
- `.dots` 的 `margin-top: 10px`（圆点与图的间距，圆点按用户要求必须留）

`align-self: start` 加了注释说明它是**双保险**——父级 `.bottom` 已有 `align-items: start`，但容器透明后「圆点被推远」这种症状更难归因，所以显式保留。

### 响应式一致性（为什么不需要额外媒体查询）

- `--banner-ratio: 2.5 / 1` 全项目只有 `tokens.css:220` 一处定义，**没有任何媒体查询覆盖它**
- `.slide` 用 `aspect-ratio` 定比例 + `object-fit: cover` 等比裁切 → 任意宽度下高宽比恒为 2.5:1，图片永不拉伸
- 断点只影响**列数**（1100px 以下 `.bottom` 由两列变单列），宽度变化但比例不变
- 两张在用图的差异：id=2 恰好 2.50，任意宽度都完整显示；id=1 是 1.79，cover 恒裁上下约 28%，左右完整 —— 该裁切行为在所有宽度下一致

## 首页 banner 第二轮：高度对齐左卡 + 指示点内嵌叠图 + 圆点化

**用户诉求**：① banner 高度与左侧卡片一致；② 指示点移到图片内部叠加；③ 指示点改为圆点；④ 圆点颜色不变。

### 一、高度对齐：三段链路 + 一个必须知道的坑

**方向与上一版相反**：上一版刻意 `align-self: start`（防白边），这一版改成 `align-self: stretch`（求对齐）。**同一属性在两种需求下取值相反，别凭「怕变形」的直觉改回去**。

链路：
```
.bottom (grid, align-items: start)
  → .banner-carousel { align-self: stretch; min-height: 0 }
    → .carousel-stage { flex: 1; min-height: 0 }
      → .slide { height: 100% }          ← 不再有 aspect-ratio
        → .slide-img { position: absolute; inset: 0 }
```

**① 最大的坑：图片留在普通流里会「反向撑大」行高。**
若 `.slide-img` 是普通流元素，`slide` 的 `height: 100%` 在 grid 算行高阶段没有基准 → 退化成 auto → 图片按自身比例算出高度（宽 543、比例 1.79 → 约 303px）。而左卡（最近记录列表）约 290px → **行高被 banner 顶大到 303** → 两张卡「一样高」但都高于左卡自身高度，且随图片比例变化。症状是「对齐看着差一点，换张图又变一个值」。
修法：`.slide-img` 与 `.slide-fallback` 都 `position: absolute; inset: 0`，让它们**不贡献任何高度**。banner 的贡献高度变成 0，行高完全由左卡决定。

**② 单列断点必须回收 flex。** ≤1100px 时 `.bottom` 变单列，banner 没有「左卡」可对齐，父高度变 auto。此时 `stage { flex: 1 }`（=`flex: 1 1 0%`）的 basis 0 会让 hypothetical 高度算成 0 → **整块塌成 0 高、图片消失**。必须 `.carousel-stage { flex: 0 0 auto }` + `.slide { aspect-ratio; height: auto }` + `.banner-carousel { align-self: auto }`。

**③ 代价要知道**：高度对齐后图片比例随屏幕宽度浮动（左卡文字换行会微调高度）。要固定 2.5:1 就必须放弃底边对齐，二者不可兼得。

### 二、指示点内嵌

模板：`<div class="dots">` 从 `.banner-carousel` 末尾移进 `.carousel-stage` 内部末尾。
CSS：`position: absolute; left: 50%; bottom: 12px; transform: translateX(-50%); z-index: 2`，删除原来的 `margin-top: 10px`（脱离文档流后外边距无效，留着只会误导）。

- 用 `left:50% + translateX(-50%)` 而不是 `left:0; right:0; margin:auto`：后者把容器拉成整行宽，会**挡住图片的点击跳转**。
- dot 的 click 加了 `.stop`：当前 dots 与 `.slide` 是兄弟节点、不会冒泡，但将来若有人把它挪进 `.slide` 就会变成「点圆点顺带跳走」。
- 移入后指示点不再占布局高度，这是能对齐的前提（原来「图 + 圆点 + 间距」必然比左卡矮）。

### 三、圆点形状

上一版 active 是 16px 宽胶囊（`--radius-pill`），已取消。现在两者都是正圆：

| | 尺寸 | 颜色 |
|---|---|---|
| inactive | 7×7 | `--card-border`（原样） |
| active | 7×7 × `scale(1.3)` | `--primary`（原样） |

放大用 `transform: scale` 而非改 `width`：后者会让相邻点跟着位移、切换时整排抖动。
**颜色严格遵守「不变」**，只额外加了一层 `box-shadow: 0 1px 3px rgb(0 0 0 / 35%)` 投影 —— 投影不是填充色，用于在浅色画面上勾出轮廓；深色画面上几乎不可见，浅灰点本身已足够。
补了 `.dot:focus-visible` 焦点圈：叠加到图片上之后，Tab 到这里必须有可见反馈。

  —— 破坏性按钮不该在 hover 时变亮（那是反向引导）。
- 附带好处：与量表「高风险」标签同族，全站危险红只剩一个来源。

**讨论过但放弃**：「头像 hover → 换成退出按钮」的 swap 方案。四个坑里两个会真出事 ——
只写 `opacity: 0` 时按钮**仍可点**（误点即登出，必须配 `pointer-events: none`）；
`hover` 在触屏不触发会导致**退出入口消失**（要 `@media (hover: none)` 兜底）。
另有「Tab 聚焦到隐形按钮」与「出现即展开」的时序问题。更关键：头像已改成 `cursor: default`
纯展示，swap 会让退出入口**比二级菜单更难发现**。用户最终决定不改。

**banner 尺寸口径（给用户出图用，已核实）**：后端 `UploadProperties.targetRatio = 2.5`、
`ratioTolerance = 0.1` → **实际比例必须落 2.25~2.75，否则上传直接拒**；5MB / jpg·png·gif·webp；
管理端裁剪器固定输出 `1200×480`。首页 banner 列实宽 ≈ **576 CSS px**（content-max 1344 − 两 28 内边距
= 1288，grid 1.2:1 + gap 20），高度随左卡（**最近记录最多 3 条**）约 250~290 → 桌面显示比例 ≈2.0~2.3、
单列 ≤1100px 才恢复 2.5 → **图两侧会被裁 6~10%**，安全区取中央 80%。

**阿里云 OSS 方案调研（未实施，仅核实事实）**：
- 代码耦合点 4 处：`UploadService.saveImage`（写盘）/ `UploadProperties` / `WebConfig` 静态映射 /
  **`ProfileService.avatarPrefix()` 头像 URL 前缀白名单**（`urlPrefix + "/avatar/"`，换绝对 URL 会直接拒存）。
- 数据量：`banner.image_url` 5 行全部指向 `/uploads/`；`sys_user.avatar_url` 71 人中仅 1 条有值。
- 依赖：本地 maven 仓库（`D:\develop\...\mvn_repo`）**已有 `com.aliyun.oss:aliyun-sdk-oss` 3.18.4**
  （jar+pom 齐全，jdom/httpcomponents 传递依赖也在）→ 可离线加依赖，不用联网。
- 多实例部署：现在本地磁盘存储会失效（传 A 机 B 机 404），**这是搬 OSS 的最大真实收益**。

**配色再换一次 → 白底反色（用户第 3 版样例，MUJTABA201566）**：

| | 常态 | 悬停 |
|---|---|---|
| 底色 | `var(--card-bg)` #ffffff | `var(--text-1)` #0b1220 |
| 箭头 | `var(--text-1)` | `var(--card-bg)` |
| 文字 Logout | 透明 | 白 |

- 关键手法：**图标 `fill: currentColor` + 只过渡 `color`**。样例是 `fill: black` /
  悬停 `fill: white` 两条独立规则，那样反色是**硬切**（fill 不在过渡列表里）；
  取 currentColor 后 fill 跟着 color 逐帧重算，反色才是渐变的。
- 红 `--risk-d-ink` 与 `color-mix` 悬停加深**全部撤掉**（`.risk-d-ink` 在 SideRail 已零引用）。
  这意味着 #124「危险实心按钮填充只能用 `-ink`」在这处不再适用 —— 它约束的是**红底**按钮，
  现在既非红底、也非危险色，靠**明暗反转**与蓝色系导航区分。
- `focus-visible` outline 从 `--risk-d-ink` 改 **`--primary`**：黑圈在黑底上会消失、
  在白底上又会和图标糊在一起；主色在两种状态下都成立。
- 保留样例的 `box-shadow: 2px 2px 10px rgba(0,0,0,0.199)` —— 白圆落在 0.62 白玻璃栏上
  几乎无边，全靠这层投影勾轮廓（与「玻璃上不加彩色投影」不冲突，它是中性黑投影）。
- 自检：`vue-tsc` 0 error / `setup_smoke` 通过 / `vite build` 2.29s，`vendor-antd` 665.72 kB 不变；
  产物里已确认 `logout-btn{...background-color:var(--card-bg)...color:var(--text-1)}` 与

### 三个关键判断

1. **`provider` 不能写进 application.yml** —— `spring.config.import` 的导入文档优先级**更低**，
   写了就把 local 文件的取值盖回去。靠 Java 字段默认值 + `matchIfMissing=true` 兜底。
   （与 api-key 那次同一个坑，见 #136）
2. **后端代传，不做前端直传/预签名** —— 直传会废掉 2.5:1 / 5MB / 扩展名三道校验，且要发凭证。
3. **`public-domain` 独立成配置且必须带 https** —— 它同时是头像 URL 白名单前缀，
   缺协议会生成相对路径式 URL（裂图但库里正常）；启动时硬校验。
