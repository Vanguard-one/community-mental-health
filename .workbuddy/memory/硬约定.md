# PsyCare 硬约定全表（1–82）

> 本文件是 `MEMORY.md` 的**展开卷之一**：`MEMORY.md` 只保留红线索引与状态，
> 这里放**完整体**（含每条约定「违反了会怎样」）。**改任何代码前先扫一遍本表。**
> 为什么这样设计 → `决策与细节.md`；更早的完整版（含长篇叙事）→ `archive/MEMORY-full-20260929.md`。

项目：社区心理健康评测与咨询系统。前端 `psycare-web`（Vue3+TS+Vite+antd-vue+Pinia+ECharts），
后端 `psycare-server`（Spring Boot+MyBatis-Plus，context-path `/api`，端口 18989）。

## 一、硬约定

| # | 约定 | 违反后果 |

| 1 | 起项目前 MySQL 3306 / **Redis 6379** / 后端 18989 三依赖在跑 | 缺 Redis → 登录成功立刻被弹回登录页 |

| 13 | 表单字段**三处齐做**：`formState` / `rules` / 模板 `a-form-item name=` | 只写前两处 = 页面没有输入框，提交必失败且构建不报错 |
| 14 | 改字段前先 grep 字段名，同步改后端必填校验 | 界面看着对、点下去报 400 |
| 15 | **服务一律用户自己启动**，我只做只读探测（`netstat`/`tasklist`/`curl --noproxy '*'`），需重启只给命令 | 脚本起的实例占住 18989 = 用户点 Run 报端口占用 |
| 16 | **同一文件的多处 `Edit` 必须串行** | 并行会读-改-写互相覆盖，报成功但内容消失 |
| 17 | 要清空某列必须用 `LambdaUpdateWrapper.set(field, null)` 显式写 NULL | `updateById` 默认忽略 null → 库里值原封不动，界面与库不一致却无报错 |
| 18 | 管理端专属能力**必须后端独立断言角色**（`SecurityUtil.requireRole`） | 前端隐藏按钮只算「不给入口」，医生拿 token 直接 POST 就能执行 |

| 20 | **DeepSeek 没有 embedding 接口**，向量化必须用第二家（通义，可切 bge-m3） | 凭记忆写会架构返工；`EmbeddingClient` 从第一天就必须是接口 |
| 21 | 提示词**固定前缀严禁含时间戳/id/随机值** | 破坏 DeepSeek 前缀自动缓存，**不报错只在账单上体现** |
| 22 | 推理模型 `max_tokens` 是**「思考+正文」共享预算**，默认给足 8192 | 思考吃光预算 → 正文为空，而 `finish_reason` 仍是 `length`（看不出异常） |
| 23 | **SSE 事件契约改动必须前后端同改**（后端发 `event:` 行） | 前端只认 `data:` 会把 `error` 的 JSON 当正文拼进气泡 |
| 24 | **LLM 密钥直写 `application.yml` 的 `psycare.llm.api-key`**，不搞占位符（覆盖靠 `PSYCARE_LLM_API_KEY` 宽松绑定） | 忘配环境变量 = 启动正常、接口全 200，发消息才发现 AI 不回话。`apiKey` 须 `@ToString.Exclude`；读取走会 **trim** 的 `resolvedApiKey()`（尾随空格 → Bearer 带空格 → 401） |
| 25 | OpenAI 兼容 API 的 models 路径 = `path` 去掉末尾**两**段再接 `/models`；base-url 去**尾斜杠** | 只去一段 → `/chat/models` **404**，报错只说「检查 base-url」。**推导逻辑必须用自己的产物跑一遍验证** |
| 26 | 服务端**改写了回复内容就必须发 `override` 事件**，且落库用同一个值 | 「用户看到的」≠「库里存的」，属**合规问题** |
| 27 | 累计落库内容要接在**「下发给前端的事件」**上，不要接上游 chunk | 降级话术不入库，事后审计读到一段用户从未看过的对话 |
| 28 | **AI 阶段机必须是纯函数**（不读 Redis/不查库/不看时钟），在线推进与重放重建共用同一个它 | 两条路径各写一份 → 「偶尔跳到别的阶段」，最难复现也最难被相信 |
| 29 | ⚠️ **顺序陷阱：先 `stageStore.load()` 再落库本轮用户消息** | 顺序反了 = **推进两次**。只在 Redis 冷启动/TTL 到期时出现，有状态时完全看不出 |
| 30 | **`turnsInStage` 与 `turns` 分开计数**（跨阶段归零），且 `decide` 每轮**最多进一级** | 用总轮数 → 阶段一路冲到底；不限每轮一级 → 一轮连跳两级 |
| 31 | **阶段只由服务端给，前端禁止本地推进**；明细**必须**带 `stage`，会话**列表故意不返回** | 前端本地 `++` 会漂移且不报错；列表带阶段 = 30 条列表 30 次 Redis 查询 |
| 32 | `FIELD_WORDS` 类词表**只能靠真实语料回归**，不能凭想 | 漏词**不报错**，只让阶段推进变慢（表现为「AI 怎么老打转」） |
| 33 | ⚠️ **危机检测两套判据、口径相反**：`hit()` 判输入（**宁宽**）、`harmful()` 判输出（**宁窄**）。**输出侧绝不能用 `hit()`** | L2 要求模型建议拨 12356、L4 要求询问自伤念头 → 用「出现危机词」判输出，每段合规回复都会被替换成危机文案（真实线上故障） |
| 34 | **危机态由服务端显式下发**（SSE `crisis` + `reason`），前端**禁止**关键词/子串判断 | 「正文含 12356 即危机」这类前端反推必错 |
| 35 | **两条危机路径文案必须分叉**：`INPUT`（真建工单）可承诺转接人工；`OUTPUT`（护栏拦下、不建工单）**不承诺** | 没工单却承诺「已转接」＝一句不会兑现的话，在心理场景比不承诺更伤人 |
| 36 | ⚠️ **`LocalDateTime` 进 Redis 必须显式注册 `JavaTimeModule`** | 裸 mapper 抛异常被 warn 吞掉 → **阶段状态永远写不进 Redis**，每轮退化为全量重放（功能看着仍对） |
| 37 | **「功能看起来是对的」不是验收标准**：吞异常 + 有等价兜底路径的组合，必须留**可核对的痕迹** | 缺陷会静默存活（#36 就是这样活下来的） |
| 38 | 先落库用户消息、再组装上下文时，`loadHistory` **必须排除本轮那条** | prompt 里本轮输入出现两次，模型倾向合并作答且白付 token |
| 39 | **面向用户的文案不得含内部标签**（风险等级/评分公式）；内部依据进 `recommendation_log`，对外另写一份 | 注入给模型的医生名单**只给**姓名/科室/职称/擅长，不给内部 reason —— 否则模型原样念出来 |
| 40 | **能直接算出来的上下文就别让模型自己查**（推荐走 L5b 注入，零额外调用） | 注入位置必须在 L1–L4 **之后**，且写清**使用时机** |
| 41 | 复用服务方法当「素材来源」前，**先看有没有写库副作用**：注入走「只算不记」入口 | 用面向用户入口 → 每轮多 3 行 `recommendation_log`，稀释统计口径 |
| 42 | ⚠️ 阶段推进在**「用户发言之后、组装提示词之前」**，`OPENING` 阈值**必须 >= 2** | 写 `>= 1` → 模型**第一次回复就落在主诉澄清**，`OPENING` 永远空转（不报错，只少一句共情） |
| 43 | **应允类判定必须「一问一答」且否定优先**（`NO_WORDS` 先判） | 中文否定与肯定共享字形（「不用」含「用」）→ 「不用了谢谢」被读成应允 |
| 44 | **动作信号（`recommend`/`crisis`）回调里只记标记**，真正动作放到 `chat.send()` 返回之后 | 回调里 `await` 会阻塞 SSE 帧解析、遮罩盖住还在流的字。`recommend` 须在**全部 token 后、`done` 前**，且与 `crisis(OUTPUT)`/`override` **互斥** |
| 45 | 起「Phase N」编号前**先去源头（`AI助手开发计划.md`）核对有没有被占用**；增量记 `N.5` | 同一文档集出现两个「Phase 3」，后来人按错的里程碑排期 |

| 149 | **`getComputedStyle(el).getPropertyValue('--a')` 在 `--a: var(--b)` 时，返回的是 `var(--b)` 原文还是替换后的值，各家浏览器不一致 —— 任何「读 CSS 变量 → 解析成值」的代码都必须自己再查一层** | 2026-10-22 给 AI 问诊页换背景配色：登录页用 `--lens-bg` 等三个 token 喂着色器，问诊页要换一组，于是写 `.chat-lens { --lens-bg: var(--lens-chat-bg) }`（一层间接引用，只为不动登录页那份）。若解析器只认 `#hex / rgb() / hsl()`，间接引用会**静默**落到兜底色（紫底）——页面整体变成另一种配色，控制台一句报错都没有。**正解**：解析前先匹配 `^var\(\s*(--[\w-]+)\s*\)$`，命中就再读一次被引用的变量（只跟一层，不做递归）；两个分支都要留，因为「浏览器已替换」时正则不命中，原解析照常工作。**判据（可推广）**：凡是「从 DOM 取一个 CSS 值再自己解析」的路径（颜色、长度、角度、时长），都要考虑「取到的是原文而不是计算值」；这类失败一定是**静默兜底**，不会报错，只能靠人眼发现「颜色不对」。另附：同值/auto 的定位元素按**树序**决定先后，所以背景层与内容层不要靠 DOM 顺序分层，内容层显式写 `z-index` |
