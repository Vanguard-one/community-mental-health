## 修「只有 user02 进 AI 问诊必显示会话已结束」

### 根因（数据已证实）

`chat.ts` 的 `restoreLast()` 拉会话列表找 `status==='OPEN'`，找不到就 `?? list[0]`。
而列表接口 `AiConsultService.SESSION_LIST_LIMIT = 5`、按 id DESC ——

| 账号 | 列表返回（前 5 条） | 结果 |
|---|---|---|
| user02 (id=7) | id 65/64/63/62/61 **全 CLOSED** | `find(OPEN)` 落空 → `list[0]` = 65（CLOSED）→ 界面「会话已结束」 |
| user01 (id=6) | 32/28/26 CLOSED，**25 OPEN**，24 OPEN | 命中 25 → 看不出问题 |

真正该打开的那条：user02 = **id 60（OPEN，14 条消息）**，排在列表第 6 位，被 LIMIT 挤掉了。
所以「会话」根本没被关闭，只是**加载错了会话**。

### 改了什么（`psycare-web/src/stores/chat.ts`，纯前端）

1. **删掉 `restoreLast()`**（含 return 导出）→ `enter()` 直接调 `open()`。
   `openSession` 本身就按 `resident_id + consult_type=AI + status=OPEN` 查、**不受列表 LIMIT 约束**，
   有就复用、没有才新建 —— 正是进页面需要的全部判断。
2. **`open()` 的短路条件**：`sessionId !== null` → `sessionId !== null && sessionStatus === 'OPEN'`。
   否则 store 里残留一条 CLOSED 会话时会一直短路，永远不重新问后端。
3. `loadSessions()` 注释加警告：不要再用列表判断「该打开哪条会话」（它现在只用于取 assessmentId）。

自检：`vue-tsc -b` 0 error；`setup_smoke.mjs src/views/consult/AiChat.vue` 通过。
纯前端 → **不用重启后端**，刷新即生效。

### 遗留（不在本次范围）

`loadSession()` 用 `sessions.find(id)` 取 `assessmentId`，同样受 LIMIT 5 影响 ——
当前会话若不在前 5 条，右栏「关联测评」卡会空。彻底修需给 `AiSessionDetailVO` 加 `assessmentId` 字段。

### 修：追问建议「思考时发虚 + 自己变回固定三条」（用户验收后反馈）

两个症状、两个独立成因，都不是「渲染抖动」这么笼统：

**① 虚影 = `backdrop-filter` + `transform` 的合成产物。**
上一版换组用了 `<Transition mode="out-in">`，进出场都带 `translateY(±4px)`，
而 `.quick-chip` 上有 `backdrop-filter: blur(8px)` —— Chrome 对带 backdrop 模糊的元素做位移时
会拿**变换前的画面**去采背景，合成出来就是一层抹开的残影。
同族记录：`.quick-chip:hover { transform: translateY(-1px) }`、`::before { transform: scale(1.2) }` 也一样要删。
现在的悬停只改描边/文字/阴影（视觉上仍「浮起来」，因为 shadow-hover 加重了）。

**② 「自动变成固定消息」= 判据用了 `sending`，而它比「本轮建议结束」早 1~2 秒。**
`sending` 在 `done` 就 false（必须如此，否则输入框被锁），但那一刻 `followups` 还是空的
→ 按 `sending` 判断就是「先亮静态兜底三条，1~2 秒后被真建议替换」。
`send()` 开头还有一句 `followups.value = []`，所以从**开始发消息**那一刻就立刻翻回静态 ——
用户的描述「思考回复时自动变成之前固定的消息」精确对应这一句。

**修法：引入第三个状态 `followupsPending`（store），把「建议行可见性」从 `sending` 解耦。**
- `send()` 开头 `followupsPending = true`；`finally`（带 `myIdx` 守卫）里置 false。
- 视图 `promptsReady = !sending && !followupsPending`，行用 `:class="{ 'quick-row--idle': !promptsReady }"`，
  CSS 是 `visibility: hidden`（**保留高度**，否则胶囊会上下跳 34px；一个回合抖两次比空着更难忍）。
- 于是时间线变成：思考中藏 → done 后仍在 1~2s 空窗里藏着 → **流关闭那一帧直接露出最终内容**。
  一回合只出现一次、只出现最终态，没有「先兜底再替换」的中间态，也就没有可动画的东西。
- 顺带删掉 `.quick-chip:disabled { opacity: 0.55 }` 和模板里的 `:disabled`：
  0.55 的半透明白片压在浅蓝渐变上本身就是「发白残影」的第二个来源；
  行都藏起来了，不需要用压暗表达「暂时别点」（点击本来就被 `applyQuickPrompt` 拦着）。
- `.quick-swap-*` 四段 CSS 与 `quickKey` computed 一并删除。

自检：`vue-tsc` 0 error、`setup_smoke` 通过、`vite build` 成功（`vendor-antd` 665.72 kB 未变）。

### 追问建议 chip 改「半透明毛玻璃」（第 20 批）

用户要求：提示消息做成半透明毛玻璃质感。这一改等于**撤回第 19 批的「实心遮挡」**，
所以先把取舍讲明再动手：玻璃 = 背后内容被**糊住**（变成光斑），不是**盖住**（完全看不见）。

`.quick-chip` 最终值：
- `background: color-mix(in srgb, var(--card-bg) 70%, transparent)`
- `backdrop-filter: blur(18px) saturate(180%)`（autoprefixer 会自动补 `-webkit-`，已核实产物）
- `--chip-hi: inset 0 1px 0 color-mix(--card-bg 90%, transparent)` + `--shadow-card`，
  hover 时必须把 `--chip-hi` 一起带上，否则悬停瞬间顶边高光消失、像贴纸被抽走一层
- 描边、圆点、字体全部不动

**透明度不是随手取的，是算出来的**（脚本实测合成底 + WCAG 对比度，`--text-2 #47536a`）：
| 背后是什么 | 70% | 65% | 60% |
|---|---|---|---|
| 页面底 #c6d9f5 | 6.98 | 6.85 | 6.73 |
| AI 白气泡 | 7.74 | 7.74 | 7.74 |
| 用户气泡亮端 #2563eb | **5.01** | 4.63 | 4.27 |
| 用户气泡暗端 #1d4fd8 | **4.75** | 4.34 ✗ | 3.96 ✗ |
⇒ **70% 是下限**，再透就破 AA（12.5px 小字对底子最敏感）。注释里写死这三个数字，
免得以后有人「再透一点更好看」。

**为什么不回到第十七轮的参数**（84% + blur(8px)）：那版被报「思考时发虚」，
真因不是透明度，而是 chip 上还挂着 `transform`（Chrome 对带 backdrop 模糊的元素位移时
拿变换前的画面采背景）。现在 hover 仍只改描边/字色/阴影，**不位移不缩放**，
注释里把这条禁令写回去了；同时把 blur 从 8px 提到 18px —— 半径小时背后的字还能看出
「是个字」，半懂不懂的鬼影最难看，18px 直接搅成均匀明暗才像玻璃。

自检：`vite build` 通过（`vendor-antd` 665.72 kB 未变）；产物里
`-webkit-backdrop-filter:blur(18px)saturate(180%)` 与标准属性并存，
`.quick-chip` 的 `box-shadow:var(--chip-hi), var(--shadow-card)` 正确；`dist` 已删。

### 输入胶囊加扩散光晕（第 21 批）

需求：输入框外层加「扩散式模糊光晕」，更柔和、有层次；要说清范围/强度/颜色/透明度、
聚焦与输入时是否动、且不影响可读性与性能。

`.composer` 的 box-shadow 从 `var(--shadow-card)`（单层 0 4px 14px 5%）改成**四层**：
| 层 | 偏移/模糊/spread | 颜色 | 作用 |
|---|---|---|---|
| ① 接触影 | 0 1px 2px | --text-1 6% | 交代「贴着底」 |
| ② 近影 | 0 6px 16px -4px | --text-1 10% | 中性结构 |
| ③ 中景影 | 0 16px 34px -8px | --primary 12% | 阴影转成光 |
| ④ 扩散晕 | 0 0 44px -4px | --primary 14% | 无方向柔光 |

要点：
- **蓝 + 灰混用**：全蓝会飘、全灰会脏；结构层用 `--text-1`，光学层用 `--primary`。
- **负 spread 收范围**：浮层左右只有 32px 内边距，正 spread 的大模糊会撞
  `.chat-main` 的 `overflow: hidden`（实测外缘 alpha <1% 看不见，但仍收几像素更稳）。
- **聚焦不插值 box-shadow**：单独做 `.composer::after`（`inset:-1px; z-index:-1;
  pointer-events:none`），里面放「4px 紧贴环 + 56px/22% 扩散晕」，只过渡 `opacity` 240ms。
  理由：box-shadow 动画每帧要重新光栅化 ~770×160 的模糊区，低配掉帧；
  opacity 走合成器，阴影只栅格化一次。
- `z-index:-1` 能落到胶囊背后，是因为 `.composer` 有 position 但**没有** z-index
  （不是层叠上下文）→ 伪元素进入 `.chat-input`(z-index:2) 的层叠上下文，
  排在胶囊背景之下、消息之上。
- **输入过程中光晕不变**（不做逐键变化）：每键改大面积阴影 = 必然卡；
  也避免「一边打字一边有东西在闪」的噪音。要「有内容时更亮」可用
  `:has(textarea:not(:placeholder-shown))`，只在首字/清空切换一次，本轮未做。
- 可读性：光晕全在胶囊**外侧**，内部仍是纯白 --card-bg，placeholder/正文对比度不变；
  它给从下面滑过的消息蒙一层 ≤14% 蓝，深色字对比不降反升。

自检：`vite build` 通过（vendor-antd 665.72 kB 未变）；产物里
`.composer` 四层 shadow、`transition:border-color`，
`.composer::after` 的 `inset:-1px/z-index:-1/pointer-events:none/opacity:0`
与 `:focus-within::after{opacity:1}` 均在；`dist` 已删。

## 第 25 批｜「没看见粒子球」的根因 + 改到输入框左侧

用户反馈看不到球。**根因是上一版我自己的 bug，不是没刷新**：

`OrbNoise` 的根节点用 inline style 写了 `width: 100%; height: 100%`
（原本是为了「不传 width 就填满父容器」）。**内联样式优先级高于任何选择器**，
于是父级的 `.input-row .composer-orb { width: var(--orb-size) }` 永远输 ——
球被撑成 **770×54**（父级 `.input-row` 的整个宽度），再按
`left: calc(100% + gap)` 往右铺开 770px，整块被 `.chat-main` 的 `overflow: hidden`
裁掉。画布内容居中在 770 宽盒子的中点（≈401px 处）→ 也在可视区外 →
**观感就是「功能没做」，但 DOM 里节点齐全、样式全对、构建全绿**。

修法（`OrbNoise.vue`）：
- `rootStyle` 只在**显式传了 `width`/`height` prop** 时才写内联尺寸，否则返回 `{}`；
- 默认尺寸交给 `.orb` 自己的 `width/height: 100%`（写在 `<style scoped>` 里），
  使用方要用固定尺寸时用**更高特异性的选择器**覆盖 —— 这条覆盖链才成立。
- 空态那颗球不受影响：`.empty-orb .orb-field { position:absolute; inset:0 }`
  与 `.orb` 的 100% 两条都给出 148px。

同时按用户要求把球从输入框右侧移到**左侧**：
- CSS：`left: calc(100% + gap)` → `right: calc(100% + var(--orb-gap, 12px))`；
- `ORB_GAP` 16 → 12；
- `syncComposerOrb()` 改量左侧走廊 `corridor = composer.left - footer.left`，
  **不减 `paddingLeft`**（`.chat-input` 没有底色也不裁剪，内边距那圈是可见区；
  上一版对右侧多减了 `paddingRight`，白白藏掉 1280~1340 这档本来放得下的球）；
- 判据从「够 54+16 才显示」改成「**优先缩球**」：
  `size = clamp(min(胶囊高, corridor - gap), 40, 88)`，`corridor - gap < 40` 才隐藏。
  走廊随窗口变（1440 约 150px、1238 约 52px、1101~1237 只剩 32px）。

**可见区间**（左栏常驻/抽屉两种形态算过）：≥1238px ✓｜1101~1237 ✗｜938~1100 ✓｜<938 ✗。

自检：`vue-tsc` 0 error、`setup_smoke` 通过、`vite build` 成功
（`vendor-antd` 665.72 kB 未变）。产物核对：`.orb` 里已是

## 第 30 批：顶部导航改「透明玻璃胶囊 + 收窄拉长」

用户要求：形状改胶囊（两端半圆）、整体宽度收窄使其更细长、边缘平滑整洁、质感要透明玻璃。
全部在 `psycare-web/src/views/consult/AiChat.vue`，**纯前端，后端未动**。

### 尺寸算式（改这三个数必须一起看）

| 量 | 旧 | 新 |
|---|---|---|
| 单项 | 70 × 50 | **64 × 44** |
| 悬停展开 | 130 | **120** |
| 内边距 | 8 | **5** |
| 描边 | 无 | **1px** |
| 整体 | 226 × 66（比 3.42） | **204 × 56（比 3.64）** |
| `.chat-nav` top | 22 | **27** = (110 − 56) / 2 |

**同心关系是这次唯一容易做错的地方**：胶囊两端要"半圆"且色块不能露缝，靠的是
「子按钮半径 = 父胶囊内壁半径」——
`56/2 − 1(描边) − 5(内边距) = 22`，而按钮 `44/2 = 22`。严格相等才同心。
所以 **padding 5 与 height 44 是绑死的一对**，单独改任一个就会在端点留下月牙形的缝
（用户说的"边缘不整洁"就是它）。窄屏同式：`50/2 − 1 − 4 = 20 = 40/2`（height 40 / padding 4）。

`border-radius` 一律 `--radius-pill`（999px）—— 不要用 `--radius-ctrl: 10px`，
10px 在 44px 高的按钮上不是半圆。

高度没有继续往下压（44 桌面 / 40 窄屏）：44px 是触控目标下限。

### 玻璃质感

- 底：`var(--chrome-bg-glass)`（rgba(255,255,255,.62)）——**结构性玻璃那一档**，
  与 SideRail 64px 窄栏、管理端 56px 顶栏同一套材质。**不用 `--card-bg-glass`(0.82)**：
  那是内容面玻璃，压在这页会动的马赛克上会盖不住图标。
- `backdrop-filter: blur(var(--glass-blur)) saturate(180%)`：`saturate` 与 `.quick-chip`
  同值（只 blur 会发灰像磨砂塑料）；`blur(18px)` 才把背后搅成均匀明暗。
- 描边 `color-mix(in srgb, var(--primary) 12%, var(--card-border))`：沿用 quick-chip 的思路
  （纯灰像表单控件、纯主色太重），12% 比 chip 的 20% 更淡，因为这是结构面。
- 顶边内高光 `--nav-hi: inset 0 1px 0 color-mix(--card-bg 92%)` + `--shadow-hover`。
  **`--nav-hi` 必须跟在每一处 box-shadow 里**（漏了玻璃会塌成透明贴纸）。
- ⚠️ `.nav-menu` 上**绝不加 transform**（第 17 轮「发虚」的成因）：居中靠
  `justify-content: center`，不能写 `translateX(-50%)`。

### 顺带修掉的一个 AA 违规

`.nav-link.is-active` 原来是 `color: var(--primary)`，落 `--primary-soft` 上只有 **4.44:1**，
不到 AA —— 而标题恰好**只在悬停/聚焦时才可见**，也就是唯一会显示出来的那一帧正好是最差的那帧。
改成 `--primary-dark`（5.71）。选中块仍保持**实心** `--primary-soft`（要做成半透明的话，
上面 13px 的字对比度就变成不确定的了）。

### 其他跟着改的数

- `::before` 悬停底色：`--panel-bg` 实色 → `color-mix(--card-bg 58%, transparent)`。
  玻璃上压实色会立刻穿帮成贴纸；58% 与底下 62% 叠起来约 84% 白。
- `.nav-icon` `left: 20 → 21` = (64 − 22) / 2，让图标在静止态 64px 里**正好居中**
  （旧的 20 对应 70px；收窄后不改会偏左 1px，居中小图标上看得出来）。
