## 排查「Milvus 明明启动了却报未启动」

用户贴出后端启动日志：LLM 探活 ✅、**Milvus 探活 ⚠️ 未通过**（`DEADLINE_EXCEEDED ... waiting_for_connection`）、

### 结论：不是故障，是**启动竞速**

时间线（北京时间）：

| 时刻 | 事件 |
|---|---|
| 14:11:13 | `milvus-standalone` 容器启动（`docker inspect .State.StartedAt`） |
| 14:11:37 | 后端启动（日志第一行） |
| 14:11:47 | Milvus 探活**失败** —— 容器才起了 34 秒，5s 超时耗尽 |
| **14:14:49** | **Milvus 首次健康检查通过**（= 真正就绪）。距容器启动 **3 分 36 秒** |

后端比 Milvus 就绪早了 **3 分 36 秒**。冷启动期间端口已被 Docker 端口转发**瞬间**映射
（`com.docker.backend.exe` 代答 TCP 握手），但容器内 Milvus 尚未服务 → 连上了没数据 → gRPC 卡在
`waiting_for_connection` → 5s deadline。

**识别特征**：报错里 `Name resolution delay ≈ 0.00009s`（解析完全正常），卡的是 `waiting_for_connection`。
→ 不是 DNS / 防火墙 / 代理 / IPv6 / 鉴权。

### 已实测排除的伪嫌疑

| 嫌疑 | 实测结果 |
|---|---|
| 容器没起 | ❌ 排除。`docker ps` = `Up (healthy)`，`StartedAt` 正常 |
| 端口没监听 | ❌ 排除。`netstat -ano \| findstr 19530` 有 LISTENING |
| IPv6 回环冲突 | ❌ 排除。IPv4 / IPv6 / localhost 三条路 curl `/healthz` 均 ~0.01s 返回 404 |
| 「第二个 Milvus 实例」 | ❌ 排除。两个 PID 是 `com.docker.backend.exe`（0.0.0.0+[::]，端口转发）与 `wslrelay.exe`（[::1]，WSL2 回环中继）—— 正常组件 |
| 代理拦截 | ❌ 排除。gRPC Java 读 `https.proxyHost` **系统属性**，不读 `HTTP_PROXY` 环境变量；且当前同一环境下探活全绿 |
| 鉴权 / 库名错 | ❌ 排除。`milvus_probe.py` **4 断言全绿**；REST 查到 `psycare` 库下 `psycare_kb_chunk` **完好存在** |

### 关键：**不需要重启后端**

读 `MilvusVectorStore` 确认建连是**惰性 + 可重试**：

```java
private MilvusClientV2 acquire() {
    if (prepared) return client;
    synchronized (lock) { if (!prepared) prepare(); return client; }
}
private void prepare() {
    try { ... this.client = c; this.prepared = true; ... }
    catch (Exception e) { closeQuietly(c); throw new MilvusUnavailableException(...); }
    //                  ↑ 失败路径**只关连接、抛异常，不置 prepared=true**
}
```

→ 失败后 `prepared` 仍是 `false`，下次任何真实索引/检索调用进入 `acquire()` 会**重新 `prepare()`**。
Milvus 就绪后第一次调用即自愈。

## 首页视觉层次优化 —— 设计方案（未实施）

用户请求：
> 「首页界面布局需要优化，目前整体视觉效果不够美观：大量元素使用白色，与页面背景不协调、缺乏层次感。
> 请先给出设计方案，暂不要修改代码。」

### 一、诊断（全部实测，未凭感觉）

**根源：全站只有「一种面」。** `--card-bg: #ffffff` 出现 20+ 处，`--panel-bg` 只用在卡片**内部**
→ **页面级只有纯白这一种面**，首页 6 个白块（hero / 3 个 entry-card / panel / banner 容器）同色同描边同阴影，
层级无处安放。

**三重分层信号同时失效**（用 sRGB→线性 + WCAG 相对亮度计算，非目测）：

| 信号 | 实测 | 基准 |
|---|---|---|
| 卡片面 vs 页面底 | **1.21:1** | ≥3 |
| 卡片描边 vs 卡片面 | **1.21:1** | ≥3 |
| 阴影 | `rgba(11,18,32,0.06)` = 6% | — |

其他硬伤：
- `--primary-soft #e7eefe` vs 背景图 = **1.04:1** → 与背景几乎同色，hero 渐变尾巴 / 菜单选中态浅蓝底**完全隐形**
- `--text-3 #94a3b8` = **2.56:1**（AA 正文需 4.5）❌ —— 却用于 `entry-desc`(12px)、`latest-time`(11px)
- antd `colorBorder: #E4EAF2` 兼作**按钮/输入框描边** = 1.21:1 → default 按钮在白色 hero 上**边界不可见**

**布局问题**：① `.entries` 是 `repeat(4,1fr)` 但只有 3 项 → 第 4 格永久空置、三卡被压窄 25%；
② 间距无系统（28/28/20 + 五套 padding）；③ 圆角混用无规则；④ **hero 反而没有阴影**（最大的块最平）；
⑤ `.bottom` 1.35fr:1fr 两栏底部差 15–35px；⑥ 权重倒挂（34px 分数挤在左下）。

### 二、一个反直觉的实测结论

**靠"压深背景"换层次是低效的。** 背景图叠主色遮罩的边际收益：
alpha 0.04 → 1.29；0.06 → 1.32；0.08 → 1.37；0.10 → 1.41。
加到 8% 时图片已快被压没，才把 1.21 提到 1.37。
→ **层次必须靠"面分级 + 阴影 + 边界"，不要再动背景。** 遮罩只加到 6%，作用仅是"压出一个台阶"。

色板变更：`--card-border` `#e4eaf2`→`#d5dfeb`（1.35）；`--text-3` `#94a3b8`→**`#64748b`（4.76 ✅）**；

圆角分级（页面级主卡 `radius-lg`，内嵌元素 `radius-sm`）。
导航栏改**半透明白 + `backdrop-filter: blur(12px)`**（项目已有先例 `AiChat.vue:970`，零新增依赖）；
导航选中态由"浅蓝底"（1.16:1 等于没有）改为主色文字 + 2px 主色下划线。次按钮改"淡主色底 + 主色文字"。

### 二、实施中发现的两个**非计划内**问题

`--panel-bg` 改成 `#eef3fa` 后与 `--bg-3 #eef3f9` **只差 1** → 400% 位移动画**退化成静止灰条**，
不报错、不报警，只会看起来像「加载卡住了」。修法：新增 `--skeleton-base`/`--skeleton-hi` 专用 token

→ 写成硬约定 #112。

**坑 3 · 手写 `-webkit-` 前缀反而吃掉标准属性**：
`DefaultLayout.vue` 里我写了 `backdrop-filter` + `-webkit-backdrop-filter` 两行，构建后产物**只剩 `-webkit-`**；

## 首页卡片半透明 —— 可行性评估（未实施，用户要求「先告诉我，别改」）

用户问：用户端首页的卡片可以实现半透明吗，好不好实现。

### 一、实测背景图色域（关键发现）

`public/app-bg.png` 1440×810、**mode=RGB（无 alpha）**，实测色域 **R 88..254 / G 175..255 / B 234..255**。
深色像素集中在 **x 0..179 与 x 1260..1439 两条侧翼带**（各约 7000 个采样点），
最深 `#0090fc`（近纯蓝）；画面内有**流线型蓝色弧线与波带纹理**（放大裁剪可见硬边弧线，疑为「增强」处理的产物）。
→ **背景不是均匀浅蓝**，这是半透明所有麻烦的根源。

**各视口下内容区（宽 min(1344, vw-48) 居中）映射到原图的 x 范围**：
1280×800 → 96..1344；1366×768 → **25..1415（近无裁切，会覆盖左深蓝带）**；1440×900 → 115..1325；
1920×1080 → 216..1224；2560×1440 → 342..1098。→ 窄视口（1280 / 1366）下卡片左缘会压在深蓝侧翼上。

### 二、对比度实测（hero 区 = 最差情形，取区域内最低值）

| 做法 | text-1 | text-2 | text-3 | primary |
|---|---|---|---|---|
| 现状（不透明白，基准） | 18.72 | 7.74 | **4.76** | **5.17** |
| 纯 alpha 0.80（无毛玻璃） | 14.7 | 6.1 | **3.7 ❌** | **4.1 ❌** |
| alpha 0.80 + blur(24px) 毛玻璃 | 17.0 | 7.0 | **4.3** | **4.7** |

- 纯 alpha 的卡片底色波动区间：`#dbe6ef ~ #fdffff`
- 毛玻璃后收窄到：`#ebf5ff ~ #fdfeff`
- → **毛玻璃不是美观选项，是可读性的必要条件**

### 三、结论（给用户的方案要点）

1. **能实现**，代码量小（4~6 处 CSS）；**但不能改 `--card-bg`** —— 它是全站 L1 主面 token，
   20+ 处引用、三端所有卡片/表格/Modal/Dropdown/表单都吃它，改了会导致管理端表格与弹窗一起半透明。
   必须新建局部 token（如 `--card-bg-glass`）只作用于首页 4 类卡片。
2. **三条路线**：A 纯 alpha（最简，实测跌破 AA ❌）/ B alpha + backdrop-filter 毛玻璃（推荐，零新增依赖，
   项目已有先例）/ C 伪半透明（保持不透明，用渐变模拟，零风险但无真实「透」感）。
3. **四个真实代价**：① 对比度（见上表）；② **卡内嵌套白块会露馅** ——
   `BannerCarousel.vue:223` 与 `RiskScale.vue:189` 都用 `var(--card-bg)` 白底，必须一并改，
   否则「半透明卡片里挖出几个白洞」；③ **滚动时卡片底色会变** —— body 背景是 `fixed`，
   卡片滚动等于「擦过」背景，滚到两侧深蓝侧翼会偏蓝（要么接受、要么把背景改 `scroll`）；
   ④ 性能 —— 首页 6 个卡片约占 56% 视口面积要跑模糊，叠加 fixed 背景滚动重算。
4. **风格提醒**：半透明/毛玻璃属「玻璃拟态」语汇，与项目既定的「科技白 + 蓝图网格」是两套视觉语言；
   上一轮刚用「白卡 + 双层阴影」建立层次，半透明等于换一套表达。
5. **建议**：若做，**只对 hero 做半透明 + 用毛玻璃方案 + 局部 token** ——
   hero 面积最大、内容最少（标题 + 2 按钮 + 波形），且当前是 `linear-gradient(白 → primary-soft)`，
   改半透明白反而更自然；entries / panel / banner 内容密集（文字、分数、图片），收益小、代价大。

### 一、B 方案 = alpha + 毛玻璃，参数由实测定

用「背景图 → 叠 6% 遮罩 → 高斯模糊（模拟 backdrop-filter）→ 不透明白按 alpha 复合 → WCAG 对比度」
逐组扫描。hero 采样区刻意取 **原图 x40..1400 / y60..360**（含左侧深蓝侧翼，宁悲观不乐观）。

| alpha / blur | text-1 | text-2 | text-3 | primary |
|---|---|---|---|---|
| 0.88 / 无模糊 | 16.57 | 6.85 | **4.21 ❌** | **4.57** |
| 0.80 / 12px | 16.65 | 6.88 | 4.23 | 4.60 |
| **0.82 / 18px（定稿）** | **16.96** | **7.01** | 4.31 | **4.68** |
| 0.84 / 16px | 17.13 | 7.08 | 4.35 | 4.73 |

**结论：纯 alpha 无论提到多白都压不住背景色差**（0.88 时 text-3 仍只有 4.21），
**毛玻璃是可读性的必要条件而非美观选项**。定稿 `--card-bg-glass: rgba(255,255,255,.82)` +
`--glass-blur: 18px`（比临界留 ~4% 余量）。复合底色区间 `#ebf5fe ~ #fbfcfe`。

### 二、实施中发现的连带问题：次按钮会「消失」

`--primary-soft #e7eefe` vs 毛玻璃复合底 `#ebf5fe` = **1.05:1** → 按钮块**完全看不出边界**
（上一版它是不透明白卡上的 tonal 按钮，换成玻璃面后这个前提没了）。

改法：**透明底 + 45% 主色描边**的 ghost 形态（描边 vs 底板 **1.90**；hover 12% 底 + 70% 描边 = 2.23）。
⚠️ **不能靠加深按钮底**：实测底越深、主色文字对比度越低 —— 纯透明 **4.68** → 主色 6% 叠底 **4.33** →
12% 叠底 **3.99**，而 hero 的 eyebrow 小字与按钮文字都吃 `--primary`，不能低于 4.5。
hover 文字改用 `--primary-dark`（5.13 ✅）补足。
